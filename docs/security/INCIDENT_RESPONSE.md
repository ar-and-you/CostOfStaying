# الاستجابة للحوادث الأمنية — إجراء أولي

**الحالة: PROPOSED.** لا يوجد فريق مناوبة أو نظام إنتاجي أو SLA معلن في `main`.

## عند الاشتباه بحادث

1. احتوِ الخطر دون إتلاف الأدلة: أوقف token أو integration مشتبه به عند الحاجة، وقيّد الوصول.
2. دوّر الأسرار المتأثرة فوراً بعد تقييم أثر الإبطال والتبعيات.
3. احتفظ بالـSHA والوقت والسجلات ذات الصلة، بعد تنقيح البيانات الشخصية والأسرار.
4. حدّد الأصول والنطاق والأثر والجهات المتأثرة، ولا تنشر تفاصيل exploit علناً.
5. أصلح السبب وأضف regression/security test إذا كان قابلاً للاختبار.
6. تحقق من الإصلاح على SHA جديد، ووثق ما تم وما لم يتم.
7. راجع الحاجة إلى إخطار المستخدمين أو الجهات المختصة وفق المتطلبات القانونية المنطبقة.

## الإبلاغ

استخدم قناة الإبلاغ الخاصة المتاحة في صفحة GitHub Security إذا كانت مفعلة؛ وإلا اطلب من مالك المشروع قناة خاصة. لا تضع الأسرار أو exploit details في Issue عام.
