# Secrets Management — v2.3

**الحالة: PROPOSED | Secret scanning وPush protection مفعّلان على GitHub لا داخل CI | لا توجد أسرار نشر لازمة لخطّي CI الحاليين**

لا تحفظ API keys أو tokens أو signing keys أو passwords في Git أو ScriptableObjects أو إعدادات العميل أو logs. التعمية ليست حماية للأسرار.

عند وجود بناء أو نشر: احفظ الأسرار خارج المستودع، وامنح أقل صلاحية، وافصل البيئات، ودوّر الأسرار عند الاشتباه.

## الفحص الحالي

- **GitHub Actions:** ملفا `ci.yml` و`core-ci.yml` يستخدمان `contents: read` ولا يحتاجان أسرار نشر. لا يوجد `security.yml` أو gitleaks workflow مخصص في الشجرة؛ CodeQL default setup مهيأ من إعدادات GitHub للمستودع، وليس من YAML موجود في الشجرة.
- **فحص التاريخ:** لا يوجد في الأدلة الحالية تقرير حديث يثبت مسح تاريخ Git كاملاً بأداة متخصصة. لا تستنتج خلو المستودع من الأسرار من غياب ملفات أسرار ظاهرة أو من قواعد `.gitignore`.
- **`.gitignore`:** يستبعد أنماطاً مثل `.env` و`.env.*` وملفات مفاتيح/شهادات محددة وملفات التوقيع المحلية. هذه حماية من الإضافة العرضية فقط؛ لا تمنع تتبع ملف سبق إضافته ولا تمحو أسراراً من تاريخ Git.
- **GitHub Secret scanning وPush protection:** آخر حالة معروفة لكليهما active حسب قراءة إعدادات المستودع في 2026-11-24؛ لم تتوفر قراءة أحدث لتأكيد استمرار الحالة. فحص الأنماط غير التابعة لمزود وفحوص صلاحية الأسرار معطّلان. لا يثبت هذا مسحاً متخصصاً كاملاً لتاريخ Git.
- **Dependabot:** كانت المراجعة السابقة بتاريخ 2026-11-22 تسجل تفعيل تنبيهات الثغرات ورسم الاعتماديات، لكن الحالة لم تُحسم مجدداً في قراءة الإعدادات بتاريخ 2026-11-24. أعادت واجهة التنبيهات `403 Resource not accessible by integration`؛ لا تُنسب حالة تنبيهات مفتوحة أو غائبة. تحديثات الأمان التلقائية معطّلة في قراءة 2026-11-24 لتجنب إنشاء PRs آلية، ولم يُضف `dependabot.yml`؛ لا تغيّر هذا دون توجيه المالك.

## متابعة Dependabot — 2026-11-27

راجع [المرحلة 72 — جرد الاعتماديات وجاهزية Dependabot](../operations/ARCHIVE_RECONCILIATION_STAGE72_DEPENDABOT_DEPENDENCY_READINESS_2026-11-27.md). لم يُضف `.github/dependabot.yml` ولم تُفعّل PRs آلية: سياسة Git الحية تعتمد الدفع المباشر إلى `main`، والاتصال المتاح لا يملك صلاحية إدارة المستودع (`admin=false`). حالة التنبيهات والإعدادات الحالية UNKNOWN / NOT VERIFIED؛ لا تُستنتج خلوها من خطأ 403.

## جرد أسرار CI المستقبلية

لا يحتاج خطّا CI الحاليان إلى أسرار نشر. تُضاف الأسرار فقط عند إدخال تكامل يتطلبها، ويفضل وضعها داخل GitHub Environment مخصص لكل بيئة.

| السر المحتمل | الاستخدام المستقبلي | الحالة |
|---|---|---|
| `UNITY_LICENSE` أو `UNITY_SERIAL` | ترخيص Unity | غير مطلوب؛ لا يوجد Unity workflow |
| `UNITY_EMAIL`، `UNITY_PASSWORD` | حساب Unity | غير مطلوب حالياً |
| `ANDROID_KEYSTORE_BASE64` وكلمات مرور التوقيع | توقيع Android | غير مطلوب؛ لا يوجد بناء Android |
| مفاتيح Apple | توقيع iOS والنشر | غير مستخدمة |

## قواعد

1. لا تضع الأسرار داخل أوامر `run` أو ملفات المشروع؛ مررها عبر آليات الأسرار المعتمدة عند الحاجة.
2. لا تستخدم مفاتيح Production في Development أو Staging؛ استخدم مواد اختبار منفصلة.
3. اجعل `GITHUB_TOKEN` للقراءة فقط افتراضياً، وامنح صلاحيات إضافية لكل job عند وجود حاجة موثقة.
4. عند الاشتباه بتسريب: أوقف الاستخدام، ودوّر السر، واتبع `INCIDENT_RESPONSE.md`.
