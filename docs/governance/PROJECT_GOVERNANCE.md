# حوكمة المشروع ومصادر الحقيقة

**الحالة:** `ACTIVE` لعمليات التوثيق والمساهمة بعد دمج هذه السياسة. لا تمنح هذه الوثيقة موافقة على قواعد لعب أو تقنية غير محسومة.

## السلطة

- مالك المشروع هو جهة اعتماد قواعد اللعب والقرارات المعمارية وتغيير سياسة Git ونطاق MVP.
- سجل ADR هو الأداة الرسمية للقرارات المعمارية طويلة الأثر.
- مواصفة القواعد هي المرجع لقواعد اللعب بعد اعتمادها؛ حتى ذلك الحين تبقى مقترحة.
- الشفرة هي مرجع ما نُفذ فعلياً، لا مرجع ما يجب أن يكون تصميمياً.
- `ROADMAP.md` يحدد ترتيب العمل والحالة، ولا ينسخ أو يلغي قراراً معمارياً.

## تسلسل فض النزاع

1. قرار مالك مكتوب وحديث ومحدد النطاق.
2. ADR مقبول ونافذ، داخل نطاقه.
3. مواصفة قواعد معتمدة.
4. وثيقة النظام التابعة لها.
5. وثائق المعمارية والتشغيل والخطط.
6. التنفيذ والاختبارات لتحديد الحالة الفعلية.
7. مواد الأرشيف والتقارير القديمة.

عند ظهور تعارض لا تحذف أحد المصدرين ولا تختر الأحدث بالاسم. افتح سجل تعارض يحدد المصدرين والتاريخ وSHA والأثر والقرار المطلوب.

## ما يصبح نافذاً

السياسات الإجرائية في هذا المجلد (ضبط الوثائق، تغيير السياسات، Git، الأدلة والوكلاء) نافذة في نطاقها بعد تسجيلها في `main`. أما ADRs الأرشيفية وقواعد اللعب المقترحة ومقترحات التكدس والاستضافة والمنصات فلا تُعتمد بمجرد وجودها هنا.

## المراجعة

تراجع السياسات عند تغيير مالك المشروع أو سياسة Git أو تكدس البناء أو متطلبات المنصة أو الالتزامات القانونية/الأمنية. يجب أن يذكر التعديل ما الذي supersedes والتاريخ والالتزام المطبق.
