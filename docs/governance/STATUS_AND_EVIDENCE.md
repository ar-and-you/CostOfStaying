# حالات العمل والأدلة

> تنبيه حوكمي: أرقام ADR المشار إليها في نسخ سابقة هي مواد أرشيفية ما لم توجد في `docs/adr/` بحالة مقبولة على `main`.

**الحالة:** ACTIVE.

| الحالة | معناها | ما لا تعنيه |
|---|---|---|
| PROPOSED | فكرة/تصميم مقترح | ليس قراراً أو تنفيذاً |
| PROPOSED FOR PLAYTEST | قواعد/قيم تنتظر اختباراً بشرياً | ليست توازناً معتمداً |
| ACTIVE | سياسة إجرائية نافذة أو قرار مقبول ضمن نطاق معلن | لا يثبت التنفيذ |
| ACCEPTED | قرار مالك مسجل رسمياً | لا يثبت اكتمال التنفيذ |
| IMPLEMENTED | الكود/الأداة موجود في SHA معلوم | لا يثبت الاختبار أو الجودة |
| VERIFIED | دليل مباشر قابل للتكرار لمكوّن/نطاق/SHA معين | لا ينتقل تلقائياً إلى مكونات أخرى |
| TBD | لا توجد إجابة/موافقة بعد | لا يملأ بالتخمين |
| ARCHIVED | سجل تاريخي غير نافذ | لا يستخدم لتوجيه الشفرة الحالية |

## حزمة الدليل المطلوبة لـVERIFIED

المكوّن والنطاق، commit SHA، الأمر أو workflow URL، البيئة وإصدارات SDK/الأداة، النتيجة وعدد tests إن توفر، القيود، وartifact/log محفوظ. يجب أن يكون SHA هو نفسه الذي يصفه التقرير.

## درجات الادعاء

- ملف Workflow موجود ≠ Workflow نجح.
- Workflow نجح ≠ تدقيق أمني شامل.
- اختبار وحدة نجح ≠ تكامل شبكة أو جهاز.
- محاكاة ناجحة ≠ توازن صحيح.
- 10 جلسات بوت ≠ 10 جلسات بشرية.
- وجود مشروع Core ≠ نقل Domain إلى Core.
