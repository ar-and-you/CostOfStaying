# سياسة التحكم بالتغيير والاعتماد

> تنبيه حوكمي: أرقام ADR المشار إليها في نسخ سابقة هي مواد أرشيفية ما لم توجد في `docs/adr/` بحالة مقبولة على `main`.

**الحالة:** ACTIVE.

## تصنيف التغيير

1. توثيقي بحت: لا يغير الشفرة أو الاختبارات أو سلوك اللعبة.
2. إصلاح تقني محدود: يحافظ على العقد والسلوك المقصود ويضيف regression test.
3. تغيير معماري: يغير حدود المشاريع أو الاعتماديات أو البروتوكول أو دورة النشر؛ يتطلب ADR.
4. تغيير قواعد/توازن: يغير RULE أو قيمة اللعب؛ يتطلب playtest أو دليل مناسباً وقرار مالك مكتوباً.
5. تغيير أمني أو بيانات: يحتاج threat/privacy review واختبارات ونطاق وصول واضح.

## متطلبات الموافقة

- التغيير التوثيقي يمكن إدخاله بعد مراجعة الاتساق والروابط والنطاق.
- القرار المعماري لا يصبح ACCEPTED إلا بعد موافقة المالك وتسجيله.
- تغيير القواعد لا يصبح APPROVED بمجرد تعديل الكود أو نتيجة محاكاة.
- أي تغيير يحذف/يستبدل سجلاً تاريخياً يذكر سبب الحذف ومصدر النسخة البديلة.

## فصل التنفيذ

افصل تغييرات الوثائق عن الشفرة والاختبارات وتحديث SDK. إذا اضطررت لدمج أكثر من نوع، اذكر سبب عدم إمكان الفصل، ونطاق الملفات، وخطة التراجع.
