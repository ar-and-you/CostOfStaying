**معيار الخروج:** كل مصدر له هوية وبصمة وسلامة وبيان حدود.

### المرحلة 1 — مصالحة المسارات والمحتوى
- إنشاء خريطة `archive → nested archive → path → SHA-256 → size`.
- مقارنة كل مسار مع `main`؛ تصنيف `IDENTICAL`, `DIFFERENT`, `ARCHIVE_ONLY`, `LIVE_ONLY`, `RENAMED`, `DUPLICATE`, `CONFLICT`.
- مراجعة اختلافات ملفات C# وPython والاختبارات وCI والـmanifests قبل أي نقل.
- استخراج Git metadata وفحص commit ancestry والـbranches/tags دون push أو force.

**معيار الخروج:** سجل فرق قابل للتدقيق مع مصدر كل ملف وقرار واضح.

### المرحلة 2 — التدقيق الفني والأمني
- مراجعة C# Domain/Core، Python simulator، الاختبارات، إعدادات SDK وNuGet، workflows، GitHub permissions، والأسرار دون عرض قيمها.
- تشغيل الاختبارات المصرح بها فقط وربط كل نتيجة بالـSHA والبيئة والأمر والـexit code.
- فحص وثائق التوثيق والروابط والـanchors والتكرار واليتيم والادعاءات القديمة.
- فحص الاعتماديات والتراخيص والصيانة وCVE وسلسلة التوريد بأدوات مثبتة الإصدارات.

**معيار الخروج:** Findings مصنفة حسب الخطورة والثقة مع reproducibility وقرار قبول/رفض.

### المرحلة 3 — انتقاء ودمج المحتوى الناضج
- عدم استيراد ملفات موجودة بالفعل أو مكررة.
- إضافة الملفات الفريدة التي تسد فجوة مثبتة فقط.
- تحديث الملف القائم بدلاً من إنشاء نظير جديد.
- حفظ المواد التاريخية في `docs/archive/` مع مصدرها وبصمتها وحالة عدم النفاذ.
- إنشاء ADR فقط عند الحاجة، وبحالة `PROPOSED` إلى أن يقره المالك.

**معيار الخروج:** أصغر diff ممكن، فهرس محدث، لا تعارضات صامتة، ولا تغيير غير معتمد لقواعد اللعب أو المعمارية.

### المرحلة 4 — التحقق المستقل والرفع

**معيار الخروج:** commit موثق، مراجعة مستقلة، أدلة CI/security قابلة للقراءة، وسجل مخاطر متبقية.
