## 7.17 — «ملفات لعبة.zip» والأرشيفات السبعة المتداخلة

- SHA-256 للحاوية: `e0a972b42f68f4c6dd23f6400e45f69e53c026850d2e85d6be2b2cf29f5094f6`.
- سبعة ZIP داخلية؛ جميعها اجتازت CRC.
- 1,692 ظهور ملف، و499 بصمة محتوى فريدة داخل الحزمة.
- 1,413 ظهوراً تكررت بصمته في المراحل السابقة، و279 ظهوراً لبصمات غير مسجلة سابقاً؛ وهي 177 بصمة محتوى جديدة فريدة.
- البصمات الجديدة موزعة على 131 مساراً معيارياً؛ 28 مساراً لها أكثر من نسخة محتوى.
- بعد استبعاد Git metadata وbytecode، جرى الاستعلام عن 91 مساراً جديداً غير مكرر على `main`: 29 مساراً موجوداً و62 غير موجود. وجود المسار لا يثبت تطابق المحتوى.

### القرارات

- ملفات نموذج اللعب القديم تحت `src/CostOfStaying.Core/` لا تُستورد؛ فهي تنشئ نموذج مباراة موازياً لمسؤوليات Domain الحالية.
- ADRs ووثائق الحوكمة الأرشيفية تبقى `ARCHIVE_ONLY`؛ لا تنتقل حالات `APPROVED` من الأرشيف إلى `main`.
- أدوات `tools/audit.py` و`tools/github_config_tests/` لا تستورد بصيغتها الحالية لاعتمادها على ملفات حوكمة وإعداد غير موجودة.
- إعدادات CODEOWNERS/rulesets الأرشيفية لا تُفعّل دون تحديد المالك ومراجعة السياسة الحية.
- لا يوجد ملف مصدر أو اختبار في هذه المرحلة يبرر استبدال النسخة الحية تلقائياً.

### ملاحظة Git تاريخية

احتوت حزمتا `CostOfStaying-final.zip` و`CostOfStaying-final 1.zip` تاريخين محليين من commitين وثلاثة commits على التوالي؛ فحص `git fsck` لم يظهر أخطاء. يحتوي الأخير ADR-027 الذي يزعم اعتماد قرارات مالك سابقة. هذا الادعاء لا يثبت من داخل الأرشيف، ويتعارض مع سجل ADR الحي الذي لا يحتوي قرارات مقبولة؛ لذلك لا يُعتمد دون قرار مالك مستقل.

## 7.18 — حزمة الرفع 8b811b0

- SHA-256 للحزمة: `6369be0250b0e7ba3da6defe1ca9eb3ec06d79e5c1e7d43515e81a960b3f24cf`.
- عناصر الحزمة الخمسة اجتازت CRC؛ `SHA256SUMS.txt` طابق 4/4.
- Git Bundle كامل وصالح، ويحتوي `refs/heads/main` عند `8b811b0c23329481dd49de0586616f75558a1f89` وتاريخاً من 23 commit.
- ZIP الداخلي يحتوي 270 ملفاً، وتطابق 270/270 ملفاً مع Git tree للـBundle باستخدام Git blob IDs.
- 258 بصمة من ملفات ZIP ظهرت سابقاً؛ 12 بصمة محتوى جديدة فقط.

### التعارض مع المستودع الحالي

- دليل الرفع مبني على `fc8dd37`. فحص GitHub الحي يثبت أن `main` كان عند `ff57444`، متقدماً 87 commit على `fc8dd37`.
- الحزمة تحذف `ROADMAP.md` وتتبنى ADR-028 لسياسة فروع هجينة، بينما `ROADMAP.md` الحي موجود ويحدد سياسة `main` الحالية. كما أن فهرس ADR الحي لا يسجل ADR-028 مقبولاً.
- لذلك تعليمات الرفع القديمة وحذف الملفات واستبدال README و`.gitignore` لا تُنفذ. لم يحدث push أو merge من الحزمة.

**القرار:** `KEEP_EVIDENCE` للـBundle والـZIP والـchecksums؛ `OWNER_DECISION` لأي محاولة لاعتماد ADR-028؛ لا استيراد مباشر.

## 7.19 — AI Documentation Toolkit والتحسين الانتقائي للمهارات

- الحزمة: 24 ملفاً، لا ZIP متداخل، CRC سليم، و23/23 بصمة في manifest مطابقة.
- المهارات الست موجودة بالفعل في `.agents/skills/` على `main`، لكن محتوى الأرشيف يختلف عنها.
- وثائق AI الحية في `docs/ai/` أحدث وأكثر اتساعاً في مستويات الأذونات وحوكمة المالك والتكاملات؛ لم تُنشأ نسخة موازية من `docs/AI/` ولم تُستبدل.
- كتالوج الأدوار الحي يغطي الوظائف؛ لم تُضف ملفات أدوار مكررة أو adapters أو prompts إلى جذر المستودع.

### التحسين الذي نُفّذ

تم دمج العناصر الناضجة من toolkit داخل المهارات الست الموجودة، مع الحفاظ على قيود `main` الحية:

1. `documentation-governance`: anchors والروابط الخارجية والمسرد وتتبع المتطلبات ودليل إغلاق المراحل.
2. `domain-core-architecture-review`: ملكية المسؤوليات وduplicate state وmutable collection escape ومخاطر API وخيار عدم الترحيل.
3. `independent-adversarial-review`: الحالات الزمنية وreplay/race والمدخلات المشوهة واستنزاف الموارد وحدود الثقة.
4. `repo-baseline-audit`: التمييز بين tracked/generated/ignored/absent ومقارنة manifests دون overlay.
5. `security-supply-chain-review`: الأصول والفاعلون وحدود الثقة وworkflow triggers و`pull_request_target` والاعتماديات العابرة.
6. `verification-evidence`: الموافقة على أوامر محددة، مدة التشغيل، وربط كل معيار بنتيجة PASS/PARTIAL/FAIL مع توثيق ما لم يُشغّل.

هذه تغييرات تعليمات مراجعة فقط؛ لم تتغير قواعد اللعب أو الشفرة أو المعمارية أو إعدادات CI أو أذونات GitHub.

## 8. ملخص قرارات المراحل

| الفئة | القرار |

| وثائق وADRs تاريخية | `ARCHIVE_ONLY` ما لم يصدر اعتماد حالي |

| سياسات ADR-027 وADR-028 | `OWNER_DECISION` |

## 9. حدود الأدلة

- فحص CRC وGit fsck والتحقق من SHA لا يثبت صحة اللعبة أو جاهزيتها الإنتاجية.
- لم تُشغّل اختبارات .NET أو Unity أو Android أو Dedicated Server على الأرشيفات.
- لا تعني مطابقة مسار أو بصمة واحدة أن جميع الملفات الأخرى متطابقة.
- لا يوجد حذف أو نقل للأرشيفات الأصلية.
