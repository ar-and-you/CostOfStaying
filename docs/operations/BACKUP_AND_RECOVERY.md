# النسخ الاحتياطي والاستعادة — متطلبات مستقبلية

**الحالة: PROPOSED.** لا يوجد Backend أو database أو Dedicated Server production محدد ليكون له backup schedule حالياً.

قبل تشغيل خدمة دائمة يجب توثيق:
- ما الذي يُنسخ (بيانات الحساب/النتائج/إعدادات الخدمة) وما لا يُنسخ (كل tick افتراضياً).
- RPO/RTO وفق أثر فقد البيانات والقدرة التشغيلية.
- التشفير والتحكم في الوصول وموقع النسخ وفترة الاحتفاظ.
- اختبار restore فعلي دوري على بيئة معزولة.
- سلامة artifacts وربطها بـSHA وسجل التغيير.
- إجراء عند فساد النسخ أو تسرب مفاتيح التشفير.

لا تعتبر `git clone` أو ZIP وثائقياً نسخة احتياطية تشغيلية لقاعدة بيانات غير موجودة. سجلات GitHub Actions تحفظ وفق سياسات GitHub ولا تغني عن backup للمخازن الإنتاجية المستقبلية.
