# Domain وCore — الحالة الفعلية وحدود الترحيل

**الغرض:** وصف الشجرة الحالية، لا إعلان قرار معماري جديد.

## الموجود في main

- `src/CostOfStaying.Domain/` مشروع مستقل يستهدف `netstandard2.1`.
- `src/CostOfStaying.Core/` مشروع مستقل يستهدف `netstandard2.1`.
- اختبارات Domain في `tests/CostOfStaying.Domain.Tests/` تستهدف `.NET 8`.
- اختبارات Core في `tests/CostOfStaying.Core.Tests/` تستهدف `.NET 10` عبر ملف `global.json` المحلي.
- يستخدم Domain واجهة `IMatchClock`، وتوجد `ManualClock` للاختبارات.
- لا يوجد Unity project أو تكامل FishNet أو خادم Dedicated Server قابل للتشغيل في الشجرة الحالية.

وجود المشروعين منفصلين لا يثبت أن هذا هو الحد المعماري النهائي. تتضمن الحزم التاريخية وثائق ADR تتناول احتمال توحيد النواة أو نقل Domain إلى Core، لكنها ليست سجلات حالية في `main`. لذلك لا تُنفذ الهجرة ولا يُعلن اكتمالها قبل استيراد سجل القرار ومراجعته.

## المحاكي والاختبارات

- `tools/balance_simulator/test_parity.py` يختبر سلوك محاكي Python وحده. الاسم التاريخي لا يعني أنه يشغّل C# أو يقارن نتائج اللغتين.
- محاكي Python أداة استكشاف، وليس مرجعاً تنفيذياً لقواعد اللعبة.
- `tools/playtest/run_sessions.py` ينتج جلسات اصطناعية؛ هذه ليست جلسات بشرية ولا تحقق بوابة اعتماد التوازن.
- نتائج الاختبارات المحلية الواردة في تقارير 2026-11-21 تخص بيئات الفحص والنسخ التي وصفتها التقارير. لا تمثل نتيجة GitHub Actions.

## غير مثبت

لم يتم إثبات بناء Unity أو Android أو iOS أو خادم شبكي في هذا المستودع. لم يتم إثبات التكافؤ بين Python وC#. لا تُرفع حالة مكوّن إلى VERIFIED دون دليل قابل لإعادة الإنتاج مرتبط بالتزام Git محدد.

## حالة الحوكمة المعمارية — 2026-11-22

لا توجد ملفات ADR معتمدة في `docs/adr/` على `main` وقت هذا التحديث. سجلات الأرشيف مرشحة للمراجعة فقط؛ بينها أرقام متعارضة، لذا لا تُعامل بوصفها قراراً نافذاً قبل المصالحة والاعتماد. يبقى الوضع الحالي هو فصل المشروعين دون إعلان أن هذا الحد نهائي. سجلت الفجوة وخطوات إغلاقها في [`docs/adr/README.md`](../adr/README.md)؛ لا يبدأ النقل أو التوحيد قبل قرار مالك موثق وخطة واختبارات مناسبة.
