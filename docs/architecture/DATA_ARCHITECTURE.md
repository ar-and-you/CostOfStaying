# معمارية البيانات — مبادئ مستقبلية

**الحالة: PROPOSED.** لا توجد قاعدة بيانات أو خدمة تخزين إنتاجية معتمدة أو منفذة في `main`.

## 1. مبادئ

- لا تجمع بيانات شخصية قبل تحديد الغرض والضرورة والأساس القانوني ومدة الاحتفاظ.
- لا تحفظ كل tick أو حالة مباراة لحظية افتراضياً.
- افصل بيانات الحساب عن بيانات المباراة وعن سجلات التشغيل والأمن.
- لا تجعل العميل مصدراً موثوقاً لنتيجة المباراة أو تغييرات الحالة.
- لا تنشئ مخططاً دائماً قبل اعتماد مزود وخطة حذف/تصدير/استعادة.

## 2. تصنيفات مرشحة

| النوع | أمثلة | التخزين المرشح | الحالة |
|---|---|---|---|
| Match runtime | Vitality, Debuffs, timers, votes | ذاكرة خادم المباراة | لا خادم منشور |
| Match result | النتيجة، المدة، إصدار القواعد | مخزن Backend لاحقاً | TBD |
| Account | معرف داخلي، إعدادات اختيارية | Backend لاحقاً | TBD؛ تقليل البيانات |
| Operational telemetry | crash, tick duration, disconnect | منصة مراقبة لاحقاً | لا منصة حالية |
| Security events | replay/authorization failures | سجلات محدودة الوصول | سياسة الاحتفاظ TBD |

## 3. متطلبات كل حقل

قبل تخزين أي حقل دائم، وثّق: الغرض، المصدر، المالك، الحساسية، هل هو شخصي، فترة الاحتفاظ، موقع التخزين، صلاحيات القراءة/التعديل، آلية الحذف/التصدير، التشفير، النسخ الاحتياطي، وأثر الاختراق.

## 4. قرار التنفيذ

مخطط الحساب، مزود Backend، منطقة البيانات، persistence، retention، الحذف، وإعادة بناء المباراة بعد تعطل الخادم كلها قرارات مفتوحة. تُحسم بسجل قرار ومراجعة خصوصية قبل التنفيذ.
