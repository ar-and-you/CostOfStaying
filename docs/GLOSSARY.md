# مسرد المصطلحات — v2.1
**الحالة: PROPOSED | يصف مصطلحات الحزمة الحالية ولا يعتمد القواعد نهائياً**

| المصطلح | التعريف المستخدم في هذه الحزمة |
|---|---|
| Alive | لاعب ما زال حياً داخل المباراة. |
| Backend | خدمات خارج خادم المباراة، مثل الحسابات والمطابقة والبيانات الدائمة. غير معتمد في ADR-003. |
| Betrayal | كلفة يكتسبها مصدر Suffering Transfer الناجحة؛ ليست نقاط فوز. عتبات الأثر غير معتمدة. |
| Collapse | حدث يزيد معدل تآكل Vitality ويطبق Debuff. لا يقتل فوراً. |
| Dedicated Server | خادم مستقل يملك حالة المباراة. المبدأ معتمد في ADR-002؛ التنفيذ المنطقي في Domain Core (MATCH.cs) والتنفيذ الشبكي مؤجل. |
| Debuff | أثر سلبي له قيمة ومدة وقابلية نقل. تفاصيل الأنواع ما زالت TBD. |
| Domain Core | النواة المجردة `src/CostOfStaying.Domain` — منطق خادمي خالص بدون Unity/FishNet (ADR-005, `DOMAIN_CORE.md`). |
| Echo Fragment | هدف تجمعه Spirit لرفع Witness Score. |
| Endgame | قواعد التصويت وإنهاء المباراة والنتيجة وفق RULE-03 وRULE-05. |
| Intent | طلب فعل يرسله العميل؛ ليس نتيجة موثوقة. يُحقق خادمياً في `Match.cs`. |
| MatchId | معرف المباراة المستخدم لربط الأحداث والتحقق من النطاق. |
| Move | نقل الأثر من المصدر إلى الهدف وإزالته من المصدر عند نجاح المعاملة. ليس Copy. |
| PSS | Proportional Set Size؛ مقياس ذاكرة العملية على Android. ليس ميزانية معتمدة. |
| RequestId | معرف طلب لمنع إعادة تطبيق العمليات الحساسة (idempotency في `Match.TryTransfer`). |
| Spirit | حالة اللاعب بعد الانتقال Alive إلى Spirit عند Vitality = 0 (ADR-007)؛ دور محايد ذو هدف مستقل، وليس موتاً نهائياً. |
| Eliminated | حالة نهائية للاعب (ADR-007) تُبلغ بعملية Eliminate الصريحة؛ معطلة في MVP. |
| Resurrect | عملية خادمية صريحة من Spirit إلى Alive (ADR-007)؛ معطلة في MVP (ADR-023). |
| Eliminate | عملية خادمية صريحة من Alive أو Spirit إلى Eliminated (ADR-007)؛ معطلة في MVP. |
| الموت (Death) | اسم سردي للانتقال Alive إلى Spirit عند Vitality = 0. ليس حالة قانونية، ولا حالة Dead. |
| Suffering Transfer | نقل آخر Debuff نشط قابل للنقل وفق شروط خادمية. |
| Vitality | مورد البقاء يبدأ عند 100 ويتآكل حتى الصفر. |
| Witness Score | نتيجة الروح المستقلة. لا تغيّر فائز المباراة. |
| CI Gate | بوابة الجودة `ci.yml` (ADR-005) — تدقيق + بناء + اختبار + محاكاة + فحص أسرار. |

## قواعد التسمية
- استخدم المصطلح الإنجليزي نفسه في المعرفات التقنية وأسماء الأنظمة.
- لا تستخدم Death وCollapse كمترادفين.
- لا حالة قانونية اسمها Dead؛ الحالات Alive وSpirit وEliminated فقط (ADR-007).
- لا تستخدم Betrayal بمعنى نقاط الفوز.
- لا تستخدم Transfer بمعنى Copy.
- إذا تغير تعريف، حدّث المسرد ومواصفة القواعد ووثيقة النظام وADR ذي الصلة.
- راجع `governance/SOURCES_AND_REFERENCES.md` للمصادر الموحدة.
