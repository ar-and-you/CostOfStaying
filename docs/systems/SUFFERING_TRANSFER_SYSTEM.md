# نظام Suffering Transfer — خط أساس مقترح للاختبار

**الحالة: PROPOSED FOR PLAYTEST.**

## السلوك المقصود

النقل Move كامل وليس Copy: عند نجاح النقل، تزال آخر Debuff نشطة قابلة للنقل من المصدر وتضاف إلى الهدف بالقيمة والمدة المتبقية نفسيهما. لا يجوز أن يبقى الأثر عند الطرفين.

## الشروط المقصودة

المصدر والهدف Alive، الهدف غير المصدر، العبء نشط وقابل للنقل، المسافة ضمن الحد المقترح، cooldown المصدر منتهٍ، والهدف لديه سعة. النقل الناجح فقط يضيف نقطة Betrayal واحدة إلى المصدر. الرفض أو replay لا يضيف نقطة ولا يترك آثاراً جانبية.

## الحدود التنفيذية الحالية

منطق النقل موجود داخل مجمّع Domain `Match`. يستقبل المجمع المسافة كقيمة يقدمها المستدعي؛ لا يوجد Network Adapter أو خادم متصل يقيس المسافة فعلياً. يجب ألا توصف هذه القيمة بأنها server-measured في المنتج الحالي قبل تكامل الخادم.

## قيم غير معتمدة

مدى 2m، cooldown 5s، وسعة Debuffs 3 هي افتراضات/قيم اختبار من الإعدادات، لا توازن معتمداً. عتبات Betrayal 3/5/7+ غير نافذة.

## الاختبارات المطلوبة

النجاح والنقل الكامل، خارج المدى، cooldown، هدف غير حي، عدم وجود عبء، سعة ممتلئة، request replay، تزامن طلبين، وفشل لا يسبب mutation جزئياً. يلزم اختبار تكاملي خادمي عند إنشاء transport.
