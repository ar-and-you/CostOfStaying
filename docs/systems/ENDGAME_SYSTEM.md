# نظام نهاية المباراة — خط أساس مقترح للاختبار

**الحالة: PROPOSED FOR PLAYTEST.** القواعد والقيم ليست نهائية.

## فتح التصويت

عندما يصل عدد Alive إلى ثلاثة، يفتح Domain تصويت Collective Surrender مرة واحدة في المباراة. القيمة الافتراضية لمدة التصويت 20 ثانية، وهي قيمة خط أساس للاختبار وليست توازناً معتمداً.

## حسم التصويت

- الإجماع المقترح هو 3/3 Yes.
- No أو Abstain يمنع الإجماع.
- عند الإجماع تنتهي المباراة بـCollectiveSurrender دون فائز فردي.
- إذا لم يتحقق الإجماع قبل نهاية المهلة، يعود اللعب وفق منطق Domain الحالي.
- أثر disconnect أثناء التصويت، وإعادة الاتصال، وتعريف الناخبين عند فقد الاتصال مسائل غير محسومة؛ لا نفترض تلقائياً أن disconnect يساوي No أو Abstain.

**ملاحظة تنفيذية لا تمثل قرار منتج:** عند فتح التصويت، ينسخ Domain اللاعبين Alive إلى `Votes` مع `Abstain` افتراضي. تبقى هذه القائمة snapshot حتى إغلاق التصويت؛ إذا انتقل لاعب لاحقاً إلى Spirit، يبقى مدخله ولا يستطيع استبدال صوته عبر `CastVote`، بينما يبقى أي صوت سابق محفوظاً. لا توجد حالياً معالجة حدث disconnect أو reconnect داخل Domain. يجب حسم أثر الموت/الانقطاع على الناخبين قبل تكامل الشبكة.

## النتائج الخمس

1. `LastSurvivor`: آخر لاعب Alive.
2. `CollectiveSurrender`: إجماع التصويت، بلا فائز فردي.
3. `TimeLimit`: نتيجة حد الوقت وفق أعلى Vitality عندما تنطبق شروطها في القواعد.
4. `Draw`: تعادل النتيجة عند حد الوقت.
5. `MutualCollapse`: لا يبقى لاعب Alive.

المواصفة تميز Draw عن TimeLimit وMutualCollapse. راجع التنفيذ الفعلي في `src/CostOfStaying.Domain/Match.cs` قبل توثيق تفاصيل ترتيب الأولويات أو الحالات الحدية. لا يوجد transport/server adapter يثبت سلوك disconnect شبكياً.
