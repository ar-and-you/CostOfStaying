# سجل القرارات المعمارية (ADR)

## الحالة في `main`

اعتباراً من HEAD المراجع `ad22b9ddb21ca48f9e30aa7f3560cf3e56f632c4` بتاريخ 2026-11-26، يحتوي هذا المجلد على `.gitkeep` و`README.md` و`ADR_TEMPLATE.md`؛ ولا توجد سجلات ADR معتمدة يمكن الاستناد إليها. الإشارات إلى أرقام ADR في التعليقات أو الوثائق لا تعوّض نص القرار أو حالته.

تحتوي الأرشيفات المرجعية على مواد حوكمة وقرارات غير مستوردة، وظهرت بينها قرارات مرقمة متنافسة، بما فيها سجلان مختلفان برقم ADR-005. لذلك لا تُنسخ المجموعة بالجملة ولا يُفترض أنها تمثل خطاً واحداً معتمداً. يسجل `ROADMAP.md` مقترح سياسة الفروع الهجين بوصفه أرشيفياً لا نافذاً على `main`. راجع [تقرير المصالحة](../operations/RECONCILIATION_2026-11-21.md) و[حدود Domain/Core](../architecture/DOMAIN_CORE.md).

## الضوابط المؤقتة

- `main` وملفاته وسياسة Git المعلنة في `ROADMAP.md` هي المرجع الحالي، مع احترام أي قرار مالك صريح أحدث.
- يبقى Domain وCore مشروعين منفصلين؛ لا تبدأ ترحيلاً أو توحيداً قبل مراجعة القرارات المتعارضة واعتماد خطة واضحة.
- لا تعتمد أرقام التوازن أو تغيّر قواعد اللعب من مواد أرشيفية وحدها.
- سجّل كل ADR جديد بحالة صريحة (`PROPOSED` أو `ACCEPTED` أو `SUPERSEDED` أو `REJECTED`)، وتاريخ، ومالك القرار، والسياق، والبدائل، والنتائج، وروابط التنفيذ والاختبارات.

## ما يلزم لإغلاق المصالحة

1. جرد كل سجل ADR من كل مصدر أرشيفي، وربط كل نسخة ببصمة المصدر وcommit/تاريخها إن توفر.
2. حل تضارب الأرقام والعناوين وتحديد السجل الأحدث وسلطته، من دون حذف النسخ التاريخية.
3. مقارنة القرارات المرشحة مع الكود ومواصفات اللعب الحالية؛ الإشارات في الكود وحدها لا تثبت الاعتماد.
4. طلب اعتماد المالك للقرارات التي تختار حدود Domain/Core أو سياسة الفروع أو قواعد اللعب.
5. استيراد مجموعة متسقة فقط، وتحديث هذا الفهرس و`docs/README.md` و`ROADMAP.md` وروابط المصدر.

حتى اكتمال هذه الخطوات، حالة المصالحة المعمارية `TBD`؛ لا تصف مجموعة الأرشيف بأنها الحوكمة النشطة.
