# ميثاق مشروع CostOfStaying

**حالة المنتج:** Pre-production. **حالة قواعد اللعب:** `PROPOSED FOR PLAYTEST`. **حالة التكدس التقني والمنصات:** مقترحة وتحتاج prototype وقراراً موثقاً.

## 1. الرؤية

لعبة بقاء نفسي جماعية تطرح سؤالاً واحداً: ما تكلفة الاستمرار؟ تتآكل Vitality بمرور الوقت. يمكن نقل المعاناة إلى لاعب آخر لتأجيل الانهيار، لكن النقل الناجح يضيف كلفة Betrayal. انتقال اللاعب إلى Spirit يمد مشاركته بعد الموت بصورة محايدة ومحدودة.

## 2. ركائز التجربة

1. ضغط بقاء مفهوم وقابل للقراءة.
2. نقل كامل لعبء قابل للنقل لا نسخه، مع تكلفة واضحة على المصدر.
3. استمرار المشاركة في Spirit دون تحويل الروح إلى قاتل أو فائز بديل.
4. ألا تكون حالة المباراة أو نتيجة حساسة تحت سلطة العميل.
5. اختبار MVP ضيق قبل إضافة المحتوى أو زيادة اللاعبين.

## 3. نطاق MVP المقترح

- أربعة لاعبين وخريطة واحدة.
- حلقة Vitality وCollapse وDebuffs وSuffering Transfer وBetrayal وSpirit/Endgame.
- قتال أساسي محدود بعد تعريفه واعتماده.
- Android كأول منصة مستهدفة في التصور.
- خادم مباراة مستقل Linux مستهدف، لكنه غير موجود حالياً.
- مدة لعب 10–16 دقيقة كهدف تجربة، وحد 20 دقيقة كقيمة أولية في مواصفة القواعد.

هذا النطاق منتج مستهدف لا وصف لما هو قابل للتشغيل اليوم. لا يوجد Unity project أو Android build أو Dedicated Server أو Backend إنتاجي حالياً.

## 4. خارج النطاق الحالي

المتجر والاقتصاد الدائم والتقدم الوصفي والخرائط المتعددة وVoice Chat ودعم 8–16 لاعباً ومكافحة الغش التجارية وإنتاج iOS. لا تدخل هذه العناصر دون تغيير نطاق موثق.

## 5. مبادئ هندسية

- Domain مستقل عن Unity/FishNet.
- Core يبقى منفصلاً عن Domain حتى قرار ترحيل موثق؛ لا تعتبر مقترحات الأرشيف قرارات.
- الخادم هو المرجع المقصود للقرارات الحساسة، لكن لا تدّع وجود خادم فعلي قبل تنفيذه.
- اختبارات حتمية واختبارات انحدار للمنطق الموجود.
- قياس قبل التحسين؛ لا ميزانيات أداء بالتخمين.
- كل قرار مؤثر يذكر البدائل والمخاطر ودليل التحقق وخطة التراجع.

## 6. بوابات الانتقال

1. اعتماد قواعد RULE-01..05 بعد لعب بشري موثق وتحليل التوازن.
2. تثبيت التكدس التقني وإصدارات Unity/FishNet بعد prototype قابل للبناء.
3. إغلاق اختلافات lifecycle وتحديد حد Domain/Core.
4. تنفيذ خادم وشبكة وسير أوامر ومصادقة قابل للتشغيل.
5. تنفيذ Vertical Slice لأربعة لاعبين.
6. اجتياز الأمن والأداء والخصوصية والاستعادة والقبول على أجهزة حقيقية.
7. قرار مالك صريح بتحويل حالة المنتج من Pre-production.
